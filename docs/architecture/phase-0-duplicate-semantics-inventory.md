# Phase 0 Duplicate-Semantics Inventory

- **Status:** Accepted Phase 0 inventory
- **Date:** 2026-07-16
- **Authority decision:** `docs/adr/0001-kit-is-authoritative.md`
- **Scope:** Current Hyper source and tests; documentation only

## Purpose

This inventory identifies Hyper symbols that consume, render, reconstruct, duplicate, or fall back from Visp Kit workflow semantics. It does not authorize a runtime change. Its purpose is to keep useful Hyper-owned orchestration while preventing Hyper from becoming a second authority engine.

The audit follows the call paths used by `run`, `next`, `start`, `quick`, `resume`, `guard`, `checkpoint`, MCP, sessions, Memory, routing, and handoff rendering. The classifications are primary dispositions: a row has exactly one classification even when its current implementation contains both useful adapter behavior and a safety defect.

## Evidence baseline

- WorkflowAction `2.0`, integration contract `2.0`, and orchestrator read contract `0.1` are current.
- WorkflowAction `2.0` supplies a canonical task action, scope, acceptance oracles, validation commands, assurance, verdict, findings, required reads, and one exact next command.
- Current contracts do not supply `taskClass`, negotiation, schema hashes, complete evidence definitions, authoritative graph or ready-sibling state, or authoritative post-checkpoint completion and PR state.
- Current compatibility evidence is limited to the exact pair and cases actually tested. The recorded live-binary baseline is an unpacked three-case drift check; packed-pair compatibility remains pending. No semver or broader support window is currently proven.
- WorkflowAction `3.0`, schema identity, negotiation, canonical v2/v3 derivation, and a wider support window are future gated design, not current behavior.

## Mode rules

| Mode | Detection boundary | Permitted Hyper behavior | Assurance ceiling | Required failure behavior |
|---|---|---|---|---|
| Genuine Kit-less | No Kit configuration or signals and local operation is explicit | Use local task, evidence, guard, review, and context utilities | `advisory` or `local_checked` | Show unavailable Kit capabilities; never imply strict coverage |
| Kit-backed healthy | Configured Kit and required artifacts are available, fresh, supported, and valid | Validate and render Kit output verbatim; manage Hyper-owned sessions and host integration | The exact Kit-provided level, including `kit_strict` only when Kit says so | Do not infer missing permission, scope, evidence, advancement, completion, or PR state |
| Configured unhealthy | Kit signals exist but the binary or required authority is missing, timed out, non-zero, malformed, unsupported, uninitialized, stale, or unevaluable | Preserve diagnostic context and render a block or inconclusive result | No strict success | Never silently fall back to Kit-less behavior or turn an unknown result into success |

Configured unhealthy is not Kit absence. Direct `start` and `quick` remain an open product choice: require an always-explicit local mode, or block them in configured strict projects. This inventory does not choose between those options.

## Classification legend

1. **retain as renderer or adapter** — Hyper owns the integration responsibility, but defects may still need a bounded correction.
2. **remove after equivalent Kit contract coverage** — the behavior competes with Kit authority in strict mode and remains only until a tested replacement contract exists.
3. **retain only for genuine Kit-less/local mode** — useful deterministic local behavior that must never be selected after a configured Kit failure.
4. **unresolved Kit contract gap** — Hyper currently needs information that Kit does not yet expose authoritatively; document and gate the future addition.

## Phase 0 disposition

The retained rows keep Hyper modular: adapters parse authoritative contracts; renderers present them to hosts; sessions, branch mapping, Memory, supported subagents, and advisory routing stay Hyper-owned. Local-only rows remain useful only behind an explicit genuine Kit-less boundary. Removal rows wait for equivalent Kit coverage, and gap rows cannot be implemented without a separate Kit contract task.

The smallest safe runtime sequence after this documentation unit is tests first: distinguish Kit absence from configured-unhealthy state, prove fail-closed callers, correct the reconciliation invocation, and fix MCP domain-status mapping in separately authorized units. Direct `start` and `quick` semantics still require a product-owner decision. No runtime behavior, compatibility claim, WorkflowAction `3.0` design, or Phase 1 work is authorized by this inventory.
